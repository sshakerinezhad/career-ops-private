## 2. What an APEX task row looks like

- APEX-Agents 1.0 (gated): task = Prompt + Rubric (binary criteria + grading target) + Gold outputs + Metadata + World context; 480 tasks / 33 worlds; 4.06 criteria/task; 9 apps / 63 tools; web search off.
- APEX-Agents 1.1 (gated): Harbor delivery: environment/ (3 shared images), tasks/ (240 dirs: instruction, metadata, agent config, environment overlay, solution, grader), worlds/ (31 seeds). Run: `harbor run -d mercor/apex-agents-1-1@1.0.1 -a apex_loop_truncated_tools_agent:ApexLoopTruncatedToolsAgent -m anthropic/claude-opus-5`.
- Harbor task dir (recipe README): instruction.md, task.toml, archipelago.json, environment/Dockerfile, tests/ (test.sh, grade.py, verifiers.json "rubric criteria (LLM-judged), hidden from agent", golden_responses.json, vendored runner/). Eval-trace trial layout: config.json, result.json, agent/trajectory.json, agent/tito_transitions.json, verifier/reward.json, artifacts/manifest.json; Pass@1 = "fraction of trials with a perfect reward of 1.0"; MeanReward = average fractional reward.
- Archipelago verifier object: `{verifier_id, verifier_version, world_id, task_id, eval_config_id: "ec_output_llm", verifier_values: {criteria: "...", is_primary_objective: true}, verifier_index, verifier_dependencies}`; grading config per verifier: type (output / trajectory / value), criteria, weight, is_primary_objective, negative_criteria, universal, tags, dependencies, artifacts_to_reference, modality; scoring_method "task_score_unweighted_and_universal_penalty", universal_penalty_cap 0.2. GradeResult: verifier_id, judge_grade pass/fail, score, grade_rationale, negative_grade, grading_prompts{system_prompt, user_prompt, raw_llm_response, parsed_result, ...}. Criterion `type` ∈ {Critical, Nice-to-have, Style / Formatting, Subjective}; `tags` ∈ {Extraction, Reasoning, Style}. Pipeline: snapshot diff → image extraction → auxiliary judge selects relevant artifacts per criterion → per-criterion judge → weighted score.
- Archipelago judge prompt (`grading/runner/evals/output_llm/utils/prompts.py`): "You are an expert evaluator grading an AI agent's work. Determine if a specific verification criterion was met based on the agent's output (final response and/or file changes). Be precise, evidence-based, and objective. <GRADING_PRINCIPLES> Focus on what the criterion specifically asks - nothing more, nothing less / Don't penalize for aspects not mentioned / Base your assessment only on the evidence provided…</GRADING_PRINCIPLES> <ARTIFACT_RULES> ONLY evaluate file content inside <ARTIFACT> tags - agent's text claims like 'I updated the file' are NOT evidence… If no <ARTIFACT> tags exist, the agent made NO file changes…</ARTIFACT_RULES>"; "<EVALUATION_STANDARD> Every specific detail in the criterion must be precisely verified with exact values… correct answer with wrong explanation is a FAIL; Conjunctive requirements ('X AND Y') require EACH component independently verified…"; tolerance rules ($153.5 = $153.50; $2.07B rounds to $2.1B; .xls/.xlsx equivalent); output `{"rationale": string, "is_criteria_true": boolean}`. Scattergun guard (opt-in per world): "If the criterion asks for a specific answer and the task prompt did not request multiple answers or scenarios, the response must commit to a single answer. Hedging between candidates (e.g. 'it could be X, but also Y') FAILS the criterion — even if the correct answer appears among the alternatives". The production 1.1 and accounting judge prompts (GEPA-optimized) are not released.
- APEX-Accounting dev row (open, data/dev.jsonl, 10 rows): keys task_id, task_name, world_id, prompt, context_files, rubric [{id, criterion_type ("Reasoning (numerical)" / "Reasoning (qualitative)"), description}], gold_output, metadata {category, subcategory, output_type, world_entity_type, estimated_completion_hours, author_role, reviewer_role}. Judge sees prompt + criterion + final output only; never trajectory, gold, or file list. Rubric rules: self-contained, one fact per criterion, outcome-based, acceptable ranges for rounding.
- APEX-v1-extended (open, 100 rows): columns Task ID, Domain, Prompt, Rubric JSON ("criterion N" → {description, sources, justification, weight "Primary objective(s)", human_rating, criterion_type ["Extraction (recall)" | "Style" | ...], dependent_criteria}), File Attachments. Judge Gemini 2.5 Pro thinking; score = mean % criteria met over 8 runs. apex-evals judge prompt (verbatim, `prompt/grading_prompt.txt`): "You are evaluating a model-generated response against a specific criterion... Criterion to evaluate: {criterion_description} Response to evaluate: {solution} Instructions: 1. First, analyze the response against the given criterion. 2. Determine if the response fully satisfies the criterion (result = 1) or not (result = 0). 3. Provide a concise explanation (maximum 2-3 sentences)... Return... {"result": <1 or 0>, "reason": "<concise explanation>"}". Grading config defaults: model gemini-2.5-flash, temperature 0.01; failed criteria retried with backoff; GradingResult = points_earned, points_possible, percentage_score, criteria_results, cost.
- APEX-SWE (open, 50 tasks): integration task dir = task.yaml, docker-compose.yaml, Dockerfile, data/, rubric/rubric.json, tests/test_outputs.py, hidden solution.py; observability = problem_statement.md, golden.patch, test.patch, test_metadata.json (F2P/P2P).
- Terminal-Bench eval traces (open): four sets × 267 trajectories (89 tasks × 3); `trajectories_index.json` rows carry task_id, final_score, trajectory_status, grading_statuses, token statistics (total, prompt, completion, reasoning, tool_calls), time elapsed, model args; per-trajectory JSON has `trajectory` with initial_messages, trajectory_messages (roles assistant/tool/user), trajectory_output (benchmark result, command_history, test_statuses, tests_passed/failed, usage_metrics), final_answer. Harness: Terminus 2 JSON-parser variant, max_steps=1000, 3-hour timeout. Dataset card computes pass@1, pass@k, and a std over 1,000 random 3-run partitions; standard error over 89 tasks ± 4.5–4.7.

## 3. Mercor writing on judges, rubrics, agreement, contamination, Pass@k, variance, failures (quotes)

- Judge design (APEX-Agents paper §4.2): "we use Gemini 3 Flash, with thinking set to low, as the judge"; judge takes "the task prompt, the agent output, a log of the changes induced by the agent's actions, and the criterion -- but not the agent trajectory"; auxiliary judge identifies the right artifact.
- Calibration: APEX-Agents Table 2: 747 criteria (3 × 249), "Accuracy is 98.5%, precision is 96.7%, recall is 98.1%, and Positive-class F1 is 97.4%"; FN 1.9%, FP 1.3%; judge graded all 480 gold outputs correctly; self-preference "mitigated by the judge not viewing the trajectories". APEX-Accounting §3.4: three experts, majority vote; raw agreement 92.8%, 89.2% unanimous, Fleiss κ 0.857; judge 97.1% accuracy; DeepSeek-v4-Flash chosen because "within noise of the best frontier judge, Claude-Opus-4.8 (High)"; "No per-model inflation". 1.1: 1,407 labelled, 354 held out, FN 5.3→8.0%.
- Rubric philosophy: criteria are "self-contained, short, descriptive statements, which can be graded as true or false"; Mean Criteria@3 "because per-criterion partial credit separates models that complete most of a task from models that fail outright"; "Rubric-based rewards serve as a way to learn from the messiness of expert human opinions."
- Pass@k: "Pass@1 answers a clearly-defined question: if you select a task uniformly from the benchmark data and run an agent once, what is the probability that it passes (i.e., meets all criteria)?"; Pass@8 "an indicative ceiling"; Pass^8 "assesses consistency"; "Repeats are aggregated into a single pass@1 figure rather than reported as a best-of score".
- Variance: "95% confidence intervals using task-level bootstrapping: we resample tasks with replacement (n=480) and recompute the task-uniform mean over 10,000 resamples"; eval traces "mean ± sample standard deviation over the 3 runs".
- Contamination: web search off; accounting documents "novel and screened against public sources"; dev-vs-held-out gaps (Opus 4.8 61.8% dev vs 48.0% held-out); training "prompts and worlds do not appear in the benchmark".
- Failure analysis: APEX-Agents §5.2 outcome classes Pass / Timeout / Zero / Partial; APEX-SWE "epistemic discipline", integration failures "Insufficient Verification 52%, Bad Environment Understanding 22%, Specification Non-Compliance 14%, Execution Failure 12%"; APEX-Accounting Appendix M: n=74 low-scoring trajectories, L1 taxonomy (Information-gathering; Instruction-following; Reasoning; Tool use; Planning/reflection; Communication; Other) with 39 L2 subclasses; "Forgetting the information, deriving a correct intermediate result and then dropping or contradicting it downstream".
